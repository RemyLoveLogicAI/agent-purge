# agent-purge v0.2.18

### Highlights

#### 1. Fixed journal blocking multiple session launches (issue #8)

- **Symptom**: With slash installed persistently, each `omp` or `pi` launch swapped the same extension file. A second terminal reported an unfinished swap on that file.
- **Cause**: The persistent `~/.omp/agent/extensions/agent-purge.ts` and the content generated at launch by `extensionSource()` were byte-for-byte identical, but `swapFile` did not compare them. It acquired an exclusive journal first, so a redundant swap locked the file until the session ended.
- **Fix**: Compare contents before swapping. If the disk already holds the desired content, return a no-op undo without creating a journal or lock.

#### 2. Recover journals held by dead processes

On `EEXIST`, read the journal. If its owner process has exited, restore and retry once. If restoration fails because the file was externally edited, report an error rather than overwrite user data. Real conflict messages now include the owner's PID.

#### 3. Safety invariants remain

Different contents still require mutual exclusion. `recover()` still reclaims only dead v2 owners; external user edits still prevent undo; old-format journals are still reported rather than automatically overwritten.
