# agent-purge v0.2.27

### Improvements

#### 1. One-click updates for source checkouts

Previously, the updater recognized standalone EXEs and treated everything else as a global npm installation. Clicking one-click update from a `git clone` launched with `node bin/agent-purge.mjs web` therefore ran `npm install -g agent-purge@latest`, updating a separate global copy instead of the running checkout.

A third installation type, `git`, is now recognized:

| Installation | Detection | One-click update |
|---|---|---|
| `exe` | Compiled build on Windows with a non-shared Node/Bun runtime | Download the Release `agent-purge.exe`, check length and SHA-256, then replace in place |
| `git` | Installation directory contains `.git` and is not a compiled build | Run `git pull --ff-only` in the installation directory |
| `npm` | All other cases | Run `npm install -g agent-purge@latest` |

Three safeguards protect the working tree:

- `--ff-only` prevents the panel from silently creating a merge commit; locally unpushed commits cause failure for the user to resolve.
- Uncommitted changes cause refusal without changing files, with the number of changes reported.
- Detached HEAD and branches without an upstream are refused; the updater does not guess `origin/main`.

Update indicators distinguish a new release version from upstream commits without a version change. For example, the badge can display `v0.2.26 (found v0.2.27)` or `v0.2.26 (N new upstream commits)`, with the dialog's latest version showing the commit count in the latter case. Only a manual refresh runs `git fetch`; opening the panel does not contact GitHub for that check.

The CLI also prints the installation type. For source checkouts, `agent-purge update --download` actually runs `git pull`; without `--download`, it only displays the command.

#### 2. Pull failures no longer appear as already up to date

A real test showed that a network failure could make `git pull` exit nonzero while stderr was treated as output, causing the panel to say that branch `main` was already up to date. Nonzero exits now raise an error and the interface shows the actual cause.

---

### Installation and upgrade

```bash
npm install -g agent-purge@latest           # npm installation
git pull --ff-only                          # source checkout, run in its installation directory
```

See release attachments for the portable executable and installer (`agent-purge.exe` / `agent-purge-0.2.27-setup.exe`).
