### New `replaceScope` distinctions

The previous term “replace” combined several different outcomes. Each host now specifies its scope:

| Scope | Meaning |
|---|---|
| `entire-system` | Replace the whole system prompt, leaving only the persona |
| `identity-only` | Replace only the identity section, retaining tool instructions and operating rules |
| `append` | No whole-prompt entry point; append the persona while retaining the native identity |
| `client-field` | Host system prompt is assembled server-side; the client can replace only one field (Auggie) |

`test/mode-support.test.mjs` prevents append-only hosts from being labeled otherwise.

### Built-in guardrail testing

In this historical test, 4 of 17 hosts had refusal, jailbreak-resistance, or prompt-injection defenses in their system prompts. CodeBuddy, Claude, Qoder, and DSH retained some after replace: Qoder retained one 133-character prefix hard-coded in a CLI constant, Claude retained one in a user-role system reminder, and DSH retained two injection-defense sentences for web_search / web_fetch. The UI marks untested cases yellow so they cannot be mistaken for confirmed removal.

### Gemini CLI removed

Gemini CLI is no longer supported. Its last test before removal measured 30,425 → 116 characters and guardrails 1 → 0. It was removed from the host list, `matrix.json`, backends, detection, path mapping, rule files, capture adapters, icons, and documentation in all three languages, leaving 24 hosts.

The **Gemini protocol** remains: Antigravity still uses `systemInstruction`, so magpie's `geminiSystem` rewriting function and the mock provider's Gemini branch remain.

### kiro and goose marked as future support

Takeover feasibility was not established for these two hosts: kiro cannot capture requests without login, and goose only appends without overriding native identity. The UI grays them out as future support rather than claiming takeover.

### Named launch added to the capability table

`lib/caps.mjs` now includes a `launch` channel based directly on actual `backends` implementations. Previously, launch-argument hosts matched none of the four channels and the UI fell back to an inaccurate project-rules-only description. Cards now indicate a missing CLI or named launch, and the drawer provides a copyable `agent-purge <host>` command.

### Verification

At release time, `npm test` passed with no failures, `node scripts/check-repo.mjs` passed, and `npm run docs:build` passed.
