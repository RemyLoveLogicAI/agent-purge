# agent-purge v0.2.34

### A dedicated WebView2 console window

- Thin packages and the installer now include `agent-purge-window.exe`: an application-owned window without an address bar, tabs, or browser account, and with the app's taskbar icon.
- This avoids the Chrome / Edge `--app` approach and the apparent Microsoft account authorization request: testing found that Edge's first launch associated an already signed-in system Microsoft account with a new profile despite `--disable-sync` and `--disable-features=ImplicitSignIn`.
- The window host now displays a native close-confirmation dialog according to the Settings page's close-confirmation and close-action choices, also asking about unsaved drafts. Window position and size are remembered.
- Without WebView2 Runtime, with an npm installation, or with the standalone `agent-purge.exe`, the app falls back to Chrome `--app`, then Edge if Chrome is absent, then the default browser.
- The build uses a pinned-version and SHA-256 WebView2 SDK, with headers checked against handwritten IIDs. `WebView2Loader.dll` ships with the package; a missing or unhealthy host does not block packaging.

### Dark mode (#19, thanks to @hzluoty)

- The sun/moon button at the top right switches between light and dark immediately and saves the choice.
- Settings adds appearance choices: automatic (follow system), light, and dark.
- The server injects `data-theme` using the saved theme on first render to avoid a white flash in dark mode. Dark colors were checked against WCAG 2.1 AA contrast, with browser end-to-end tests covering five pages.

### Verification

At release time, `npm test` passed 90/90; `npm run check:repo`, `npm run test:package`, and `npm run test:artifacts` passed. Real-machine checks covered packaged window launch, repeated launch bringing the same window forward with the same window PID, cancel and confirm close paths, window-size persistence, a WebView2 data directory without an associated account, and Chrome fallback when the host was absent.
