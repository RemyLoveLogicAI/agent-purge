# agent-purge v0.2.20

### Highlights

#### 1. Fixed dsh 0.2.2 plugin `ERR_MODULE_NOT_FOUND` (issue #11)

- **Symptom**: After upgrading to `@deepseek-ai/dsh` 0.2.2-rc.1, startup reported that the `agent-purge` package could not be found from the web profile directory.
- **Cause**: Plugin packages had been written manually into each profile's `node_modules`. Starting with dsh 0.2.2, profile dependencies are managed by pnpm's runtime resolution table. When that directory was cleaned or rebuilt, the bare package name in the patch could no longer resolve. The same stack was reproduced locally.
- **Fix**: Store the plugin package in `~/.agent-purge/dsh/<plugin-name>/` and reference it from the patch using an absolute `file:` URL. Reinstalling profile dependencies, deleting `node_modules`, or changing dsh versions no longer affects loading. Old-layout copies are migrated and cleaned up on the next `install`.
- The plugin reads the host's `profileContext` at runtime rather than guessing the profile from its path, with the old path inference retained as a fallback. `dshProfiles` selections and per-profile `/purge` state remain accurate with one plugin package.
- **Verification**: Real `dsh web` runs on `0.2.1-rc.5` (desktop CLI) and `0.2.2-rc.1` produced no `did not activate` warning; `dsh.log` recorded `apply … profile=web`.

#### 2. Fixed hidden Windows `--app` windows and white artifacts (issue #9)

- **Cause**: `lib/window.mjs` launched browsers with `windowsHide: true`. On Windows, libuv translated this to `SW_HIDE`. If Edge was not already running in the background, the Chromium main window was created with `WS_VISIBLE = 0`, resulting in a titleless, click-through window with no taskbar icon and a white DirectComposition rectangle left on the desktop.
- **Fix**: Browsers are GUI applications, so launch them with `windowsHide: false` to ensure a visible, interactive window.

#### 3. Attach to an existing service and open a window when the port is occupied

- **Symptom**: If an old instance was running, for example after double-clicking `agent-purge.exe` again or before a previous session had fully exited, port 7788 reported `EADDRINUSE` and the process exited silently with no window.
- **Fix**: On `EADDRINUSE`, probe `http://127.0.0.1:7788/api/state`. If a healthy agent-purge service is present, call `openAppWindow()` against it and exit normally.

#### 4. Compliance and disclaimer improvements

The README and `docs/LEGAL.md` emphasize that this project is a local multi-host configuration management tool, prohibit adversarial or unauthorized access, and do not distribute unlawful or jailbreak payloads.

#### 5. Fixed local service exiting on Web console refresh (PR #10)

- **Cause**: Page unload on F5 or Ctrl+R triggered `pagehide` and sent `/api/exit`, which the server treated as immediate shutdown.
- **Fix**: Decouple page unload from shutdown and report a generation identifier through `/api/leave?gen=N`. The server uses a 1500 ms exit grace period; a new request on refresh cancels the countdown, and late beacons from old pages are ignored. Source-mode operation never exits merely because a page leaves.

---

### Upgrade from 0.2.18

- 0.2.19 was not released separately. This version includes all fixes from 0.2.19 and 0.2.20.
- After upgrading, dsh users should run `agent-purge install dsh` once to migrate the old layout from profile `node_modules` to the data directory. Afterward, plugin reinstallation is not needed merely because dsh or its dependencies are upgraded.

### Installation and upgrade

```bash
npm install -g agent-purge@latest
agent-purge web
```

See release attachments for the portable executable and installer (`agent-purge.exe` / `agent-purge-0.2.20-setup.exe`).
