# agent-purge v0.2.29

### Improvements

#### 1. Linux release artifacts: standalone binary, `.tar.gz`, and `.deb`

Linux users previously had to use global npm installation or source. `release.yml` now has a `build_linux` job cross-compiling `linux-x64` and `linux-arm64` with Bun. Each architecture produces:

| Artifact | Description |
|---|---|
| `agent-purge-<version>-linux-<architecture>` | Standalone binary with runtime; make executable with `chmod +x` |
| `...-linux-<architecture>.tar.gz` | Portable package with `.desktop`, 512px icon, `LICENSE`, `README`, and rootless `install.sh` |
| `...-linux-<architecture>.deb` | Installs into `/opt/agent-purge`, registers `/usr/bin/agent-purge`, a desktop entry, and hicolor icons |
| `...-linux-<architecture>.AppImage` | Produced only when the runner can obtain `appimagetool`; not a hard dependency |
| `linux-manifest.json` | SHA-256 summary for these artifacts |

`scripts/build-linux.mjs` runs a real smoke test on the local architecture (`--help`, `status`, `--serve` static assets and version), then reads back `.deb` metadata and file listings before passing. Package file permissions are explicitly normalized rather than inherited from the host.

`test.yml` adds a `linux-package` job that builds on every push to guard against regressions.

#### 2. README support tables revised in three languages

The old table had three problems: blank lines split the Chinese table; its three headers mixed capture, BYOK, and rule channels into the same-session switching column; and seven harnesses were missing, including Qwen, Gemini, Crush, Kiro, Kilo, Antigravity, and PI-Desktop.

All three README tables now have five columns: harness, verified version, main takeover channel, same-session hot switching, and verification status with test details. They cover 19 harnesses.

#### 3. Project Rules page renamed and extended to global scope

The page is now called Rule Files, with scope selection (current project or global directory) and persona selection. Its status shows the written persona, and an update action replaces the managed block in place. The global side covers eight tested locations (Pi, Claude Code, omp, Grok, ZCode, Antigravity, Kilo, and Crush), using original-byte stash snapshots and removable managed blocks.

### Verification

- Built x64 and arm64 on Ubuntu 24.04; smoke tests for read-only `--help`, `status`, Web assets, and running version 0.2.29 passed.
- Installed the `.deb` with `dpkg -i`, verified `agent-purge --help` and `status`, and confirmed the command and desktop file were removed by `dpkg -r`.
- The portable `install.sh` installed to `~/.local/bin` and placed the `.desktop` file and icon.
- The standalone binary ran with no Node on `PATH`; `file` identified the arm64 artifact as `ELF 64-bit LSB executable, ARM aarch64`.
- On Windows, `npm test` reported 80 tests and 0 failures; `npm run check:repo` checked 184 committable files.

### Installation and upgrade

```bash
npm install -g agent-purge@latest                       # npm
sudo apt install ./agent-purge-0.2.29-linux-x64.deb      # Debian / Ubuntu
tar -xzf agent-purge-0.2.29-linux-x64.tar.gz && sh agent-purge-0.2.29-linux-x64/install.sh   # rootless
```

See this release's attachments for Windows portable and installer builds and the macOS `.dmg`. AppImage availability depends on whether the build runner can obtain `appimagetool`.
