# agent-purge v0.2.24

### Fixes and improvements

#### 1. Automatic in-place repair of legacy DSH configurations

- **Background**: Version 0.2.19 and earlier installed plugins into each profile's `node_modules` and referenced bare package names in `cordis.patch.yml`. The host's pnpm v11 prunes directories not declared in `package.json` when installing plugins or reorganizing dependencies, causing DSH startup to fail with `Cannot find package 'agent-purge'`. Installing other plugins could also fail until agent-purge was reinstalled.
- **Self-healing**: `healStaleProfiles()` is now invoked during `status` and `probe`. If the newer plugin package exists in the data directory, it rewrites legacy bare package names as canonical absolute `file:` URLs, removes leftover root-level empty YAML arrays `[]`, and safely removes the old copies under `node_modules`.
- **Stricter status**: `blockAlive` verifies that the patch block contains a canonical `file:` URL and the data directory actually contains the file, preventing false positives after old copies are pruned.
- **Audit trail**: Repair actions are logged automatically to `<data-directory>/dsh.log`.

#### 2. DSH cross-version testing and request capture

- Real-machine tests verified compatibility with DSH 0.2.1-rc.2 (loader 1.0.6), 0.2.1-rc.5 (desktop Electron), and 0.2.2-rc.1 (loader 1.1.0).
- Local loopback capture verified the actual model-bound prompts for all four modes. In the test, `strict` reduced the host's default 2,729 characters to a 112-character persona, removing the host identity statement.

---

### Installation and upgrade

```bash
npm install -g agent-purge@latest
agent-purge status
```

Existing DSH users do not need to reinstall manually. After upgrading, run `agent-purge status` once or open the Web interface to trigger automatic in-place repair.

See release attachments for the portable executable and installer (`agent-purge.exe` / `agent-purge-0.2.24-setup.exe`).
