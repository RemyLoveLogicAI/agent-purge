# agent-purge v0.2.37

### Windows startup no longer waits on unreachable mapped network drives (#22)

- Startup detection scans drives `C:` through `Z:` for desktop hosts. On disconnected network mappings, `existsSync` waited for SMB timeout, measured at approximately 21 seconds per drive, blocking Node's event loop: `GET /api/state` took over 40 seconds and the console remained on the persona-description loading screen while heartbeats also queued.
- Detection now reads `HKCU\Network` for mapped drive letters (language-independent, approximately 12 ms, cached for five minutes), excludes network drives, and probes local drives only (0–1 ms each). On the reporter's machine, `detect()` took 49.4 seconds; local measurements after the fix showed `fixedDrives()` at 23 ms initially and `detect()` under 0.4 seconds.
- Session-only mappings absent from the registry (`net use /persistent:no`) may still time out once. After a slow drive is observed, the process does not query it again, including when the drive-letter cache refreshes.
- Desktop hosts installed on network drives can still be located using Start Menu shortcuts and registry uninstall entries. Manually specifying scan roots with `AGENT_PURGE_DRIVES` remains supported.

### Antigravity 1.5.12 retest

- Capture and matrix retested `agy` 1.5.12: `off` 16,440 characters; `strict / replace / append` 16,933 / 16,906 / 16,905. This is still append, not replacement: `<identity>` remains intact.
- A size limit was observed: 8,000 characters of global rules entered the prompt in full, while 10,000 characters were replaced by a `<truncated N bytes>` placeholder and the persona silently lost. `settings.json`'s `rulesTokenBudget` had no effect, so large persona files need to be shortened first.
- Desktop app 2.33.0 received static inspection only: `language_server.exe` still contained the same `~/.gemini/config` rule-loading strings. GUI capture was not performed; the compatibility notes explain why.

### Verification

At release time, `npm test` passed 293/293 across 23 test files, and `npm run check:repo` and `npm run test:package` passed. New regression tests assert that mapped network drives receive no `existsSync` calls, a slow drive is not queried again on the next detection pass, and local drives remain listed after filtering.
